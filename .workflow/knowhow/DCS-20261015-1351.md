# 打包铁律：安装包与绿色包必须包含全部汉化资产

用户明确要求（2026-10-15）：「打包的时候必须打包齐全」「请确保打包的时候把所有的汉化都带上」。

## 事故背景（真实踩坑）

CMO 汉化项目 v4.1.3 及更早的安装包与绿色包，**从未包含**下列三组资产：
- `WW\PlacenameSets\{Synoptic,Cities}\0000_0000.wwp`（地图地名集 → 地图国名/城市名）
- `Symbols\Menu\*.png`（13 张中文按钮图 → 主工具栏按钮文字，文字是画在位图里的）
- `Launcher\Localization\stringsChinese.resx`（启动器中文文案）

后果：用户装包后**工具栏按钮与地图仍是英文**，而开发者本机因早年手工把这些文件拷进游戏目录而显示中文，
造成「本地全好、用户全英文」的假象，反复被用户反馈。

## 强制要求

1. `scripts/package.sh` 末尾的「汉化资产覆盖率断言」必须保持通过；缺失即构建失败，不得绕过。
2. 新增任何汉化资产时五处同步：① 收录 `assets/`；② `build.sh` 内嵌资源；
   ③ 安装器 `Deploy*` 部署 + 卸载 `Restore*` 还原（覆盖前写 `.orig` 备份）；④ 绿色包携带；
   ⑤ 覆盖率断言清单加入该资产。
3. 发布前实测核对：`grep -a <资源名> build/CMO_Chinese_Setup_v<ver>.exe` 确认内嵌；
   解包 `CMO_Chinese_Pack_<ver>.zip` 核对条目数与各资产数量。

## 另一类同类陷阱

**位图管按钮文字、词典管悬停提示**：替换按钮位图 ≠ 提示语已汉化。
例：工具栏「自动交战/手动交战」按钮位图已是中文，但悬停提示 `Auto Engage Target` /
`Manually Engage Target` 仍英文——因为词典完全没有这两条整串词条（引擎按整串精确匹配）。
