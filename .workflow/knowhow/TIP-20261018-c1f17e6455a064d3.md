# 动态拼接文本的规则化原则（整串表优先 → 形态闸门 → 只翻框架 → 反向对照）

## 场景
游戏很多文本是**运行时拼装**的，词典枚举不完：条令值 `Inherited, Always Fire`、
`2 Sorties (Maximum)`、`AvGas (200k Liter Underground Tank)`、消息日志
`AIM-120C-7 AMRAAM P3I.3 #925's Endgame Report HIT`、`BOGEY #149 now platform-classified: Tu-22MR Backfire C`。

## 四条原则（2026-10-17 落地，实测有效）
1. **位置：放在全部「整串查表」之后**。规则一旦放在精确匹配之前，就会抢走已有词条的整串
   （例：`Inherited, Pessimistic` 已有词条，若规则先跑就会翻成「继承自上级，Pessimistic」而退化）。
   本项目把规则放在 `DoTranslate` 的「归一化整串匹配」之后。
2. **先过形态闸门**：只对「看起来就是那一类」的文本动手，明文列关键词/正则前缀
   （消息日志只认 `#'s Endgame Report`、`now platform-classified`、`New <type> contact (`、
   ` vanished`、` jamme`、` spoo`、`has been destroyed!`、`New contact! Designated `），
   并加长度上限（≤200）——形态越窄，误伤越小。
3. **只翻框架，专有名词留原文**：`… #925 的终局报告：命中`、`新建武器接触（MISSILE #381）`、
   `BOGEY #147 已消失`。武器/单位/型号名保持英文反而更可用，也避免了「半截翻译」。
   术语一律复用词典既有译法（`终局报告`、`平台现已分类`、`新空中目标接触`、`未能欺骗`、`已被摧毁`）。
4. **每条规则都要有反向对照**：写完用手边的「同词干长句」试一次，确认不被吃掉。
   本轮实测：`Generic Chaff Salvo [5x Cartridges] spoofed SARH Seeker` → 中文；
   而正文长句 `The missile was spoofed by chaff but the pilot decided to continue …`
   **保持原样**（因为规则要求左侧是带 `[]` 的干扰物名）。这条对照比正向用例更能防事故。

## 验证方式（本项目可复用的捷径）
引擎自带 `XLATE_BATCH <file>` 只读探针：把从审计日志（`CMOLocalizer_LiveAudit.log`，
引擎自记的未译英文清单）里取到的**真实字符串**批量喂进去，逐条比对输出即可——
不需要复现战场事件，也不依赖界面采样。建议同时准备 1 条反向对照。
