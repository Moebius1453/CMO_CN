# 汉化事故：数据库查看器详情面板空白（游戏按控件文本分派时不得汉化其选项）

## 现象
CO【数据库查看器】打开后可以筛选、列表有数据，但点击任何装备条目，下方详情面板（WebView2）一片死灰；
点击时中文还会闪一下变回英文（用户原话：「数据库不显示数据了」「点一下装备中文就闪下变成英文」）。

## 根因（可复用的失效模式）
游戏用 `InternalDBViewer.CB_ObjectType.Text` 做**表分派**：异常栈实证
`DarkListView.OnMouseDown → DarkListView.SelectItem → InternalDBViewer.DisplaySelection →
DisplayInfoInDetailsPanel(_SelectedObjectID, _SelectedObjectType)`。
本工程的引擎把汉化铺到通用下拉框路径
（`TranslateControlTree` → `LocalizeComboBoxSafe` → `TranslateComboItems` → `TranslateDBComboItem`），
把该控件选项从 `Aircraft` 改写成「飞机 / 航空器 (Aircraft)」；`switch (cb.Text)` 的所有分支随即落空 →
`RenderedHTMLString` 恒为 0（不生成详情 HTML），且 UI 轮询每轮重译造成中英闪烁。
专用路径 `LocalizeDBViewerComboBox` 早就跳过该控件，但通用路径先执行，保护形同虚设。

## 教训与预防
1. **只要游戏按控件文本分派，就不能改写其选项文本**（宁可在界面上显示英文 token）；
   专用白名单必须覆盖通用路径，否则等于没有。
2. 诊断口径：`RenderedHTMLString` 长度（引擎 `DB_INSPECT` 命令）——正常 3.4~5.9 万字节，空白即 0。
   WebView2 子窗口标题为 about:blank、body.innerHTML 仅 41 字节，也是同一故障的可观测特征。
3. 该查看器窗体在辅助 UI 线程创建，`Application.OpenForms` 永远查不到 → 必须用
   `EnumWindows` + `Control.FromHandle` 回退（`FindDBViewerForm`），否则所有 `DB_*` 诊断命令报「not open」。
4. 程序化设置下拉框 `SelectedIndex`（`DB_SET_FILTER`）不会触发游戏的用户事件处理器
   （SelectionChangeCommitted 语义），用它验证筛选联动会误判「筛选失效」；必须真实点击下拉框并提交。
5. 不要连续多次 `CLICK_MENU 数据库查看器`（会堆叠多个查看器实例并使引擎命令通道卡死，PING/命令全部超时）。
