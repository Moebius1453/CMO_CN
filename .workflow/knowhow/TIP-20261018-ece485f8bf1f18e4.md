# 表层症状（英文/频闪）常常是「注入静默失效」的下游，别先改熔断阈值

## 症状与误判方向
游戏更新后出现：① 界面大面积英文（状态栏、HUD、条令下拉值、编队燃料…）；
② 同一处文本**中英交替频闪**；③ 引擎日志里开始出现写拉锯熔断 `WRITE LOOP BLOCKED ... after 7 identical writes`。
这时最容易走的两条错路：
- 把频闪当成「重译太频繁」→ 去调熔断阈值/加冷却 —— 只会把问题从「闪」变成「永久英文」；
- 把英文当成「缺词条」→ 逐条补词典 —— 补多少都不生效，因为**注入通道整条断了**。

## 正确顺序：先看引擎自己的注入日志
本轮（2026-10-17，游戏 1900.20 → 1900.23）的真相：
- 日志里**既没有** `Set <anti-debug 字段> ... ` **也没有** `Successfully pre-populated ...`，
  而此前每次启动都有 → 说明注入函数根本没走到写入那一步（反射按名字取字段全为 null）；
- 于是**显示层文本由游戏按自己的英文池重建**，而引擎每帧/每轮又把中文写回去 → 两边互搏 = 肉眼频闪；
  熔断计数到 7 次后把该控件永久静音 → 文本停在英文。
- 修复方式是把注入点改成结构特征探测（见同主题另一条 knowhow），注入恢复后
  **条令窗口（历史熔断现场）反复开关采样，新增熔断 0 条、文本稳定**——不需要动任何熔断参数。

## 记忆锚点（一句话）
「**先问是不是注入没生效，再问是不是缺词条，最后才怀疑熔断策略**」。
判据：日志有没有 `pre-populated`；池内关键偏移（`时间:`/` - 标准时: `…）是不是中文；
只有在「注入正常但个别控件反复回滚」时，才去动熔断/重译时机。
