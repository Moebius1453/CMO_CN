# 游戏构建更新后的汉化适配流程（结构探测 + 偏移复核 + 版本双号）

## 什么时候用
Steam 推送了新的游戏构建（游戏标题里的 `Build` 号变了）。此时汉化**几乎一定会大面积失效**，
而且失效方式很隐蔽：注入按名字反射定位，游戏重新随机化混淆成员名后，反射取字段全是 null，
旧代码没有失败日志 ⇒ **静默失效**。用户看到的是「到处是英文 + 中英频闪」。

## 四步适配流程（2026-10-17 实测 1900.20 → 1900.23）

1. **先确认构建号**：唯一可靠来源是运行时标题串 `Command: Modern Operations v1.10 - Build <n>`
   （游戏 exe 的 FileVersion 是 1.0.0.0，Steam 的 buildid 是另一套编号，都不能用）。
   引擎启动时抓一次并记录（`NoteGameBuild`），与安装清单里的 `game_build` 比对，不一致就写告警。
   **代码里不要写死构建号**——旧代码写死 `1900.20` 正是那次事故的一部分。

2. **注入点改「名字优先 + 结构特征兜底」**，不要只按名字取：
   - 结构判据：类内同时存在**静态 `List<string>` + 静态 `List<int>` + 静态 `byte[]`**（三者在类内唯一）；
   - `byte[]` 可能有多个候选（实测一个是 0 字节空数组），按**长度最大**消歧；
   - 写入方式不变：中文 `Add` 进 `strList`，偏移 `Add` 进 `offList`，再把新索引按 4 字节小端写进 `buf[off]`；
   - anti-debug 之类非必需字段取不到就**明确记日志跳过**，不要静默。
   - **每个失败分支都要有日志**（程序集缺失 / 类未找到 / 字段不全 / buffer 未初始化 / 池未就绪）——
     这次事故的核心教训就是「失败得无声无息」。

3. **偏移必须先核验再信任**（`dict/strings_pool.json` 是「偏移→英文源串」的权威表）：
   用只读探针导出本构建的「偏移→当前字符串」全表（本项目 `POOL_DUMP` 写 TSV），与词典断言逐条比对：
   命中即保留、错位重采、查无则剔除。**实测跨构建偏移零漂移**（3522/3523 命中），但必须每次核验——
   若偏移整体移位而我们照旧写入，会把中文写到**别的字符串**上（界面错字，比英文更糟）。
   同一轮要检查**偏移表里有没有源码字面量**（例如 `, 'Aircraft', '`），那类串绝不能注入。

4. **改完按顺序放行**：引擎编译 → 部署 → 只读探针实测（注入日志 + 池内关键偏移中文）→
   词库补该构建新增文本 → 全门禁（静态/安装器/实机）→ 版本提升 → 打包 → 发布。
   **发布物必须同时写清两个号**：本补丁版本 + 适配的游戏内部版本（应用/发版说明/README 四处），
   并加「构建号哨兵」回归用例（引擎报出的构建号 == 仓库声明值，否则直接红）。

## 判断适配是否成功的三条硬证据
- 日志出现 `Successfully pre-populated N translated strings`（本轮 3525 条）且无 `offset injection disabled`；
- 日志出现 `GameBuild: detected game internal build <n>` 且 n 与 `GAME_BUILD` 一致、无「警告！」；
- 池内状态栏/HUD 关键偏移（`时间:`、` - 标准时: `、` - 当地: `、`视高:`、` 显卡: `）取值是中文。
