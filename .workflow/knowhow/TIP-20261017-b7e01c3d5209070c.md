# 「叠译」的确切根因：值里含源串 + 中文短路的括注通道

## 现象
同一段译文被套了两层，例如页签显示「三维态势联动（三维态势联动 (Tacview))」、工坊页签显示
「创意工坊 (创意工坊 (Steam Workshop))」。第一眼容易误判成重复写入或 UI 重绘问题。

## 根因（本仓库实测，2026-10-17）
`src/engine/CMOLocalizer.cs` 的 `TranslateString` 有两段必须一起看：
1. 精确查表命中直接返回（`exactMap`）；
2. **只要原文里已含中文，就不再走整句翻译，只剩 `TranslateBracketSegments`**；
3. 该通道用正则取 `(X)` / `[X]` 里 2–120 字符的非中文片段，交给 `LookupPiece` 再查一次表。

因此凡是「值 = 中文 (英文字典键)」的词条（如 `Tacview → 三维态势联动 (Tacview)`），
一旦这段文字被**第二次**送进 `TranslateString`（WPF 周期性补扫、控件文本回写重入等），
括号里的英文键会被再替换一次 → 双层。
全词典这类形态目前有 1370 条，但只有在「控件文本会被重译」的路径上才会显形：
实测 TabPage 文本会踩（所以页签叠译），ComboBox 的 Items 只翻译一次则不会。

## 修法（R20 / R29-1 两次落地，同一套）
1. **让值幂等**：值里不得再出现源串，去掉括号英名（`Steam Workshop → 创意工坊`、
   `Tacview → 三维态势联动`）。
2. **补自愈项**：把已知脏形态映射到干净值，例如
   `「创意工坊 (Steam Workshop)」→「创意工坊」`、`「创意工坊 (创意工坊 (Steam Workshop))」→「创意工坊」`
   （精确查表优先于中文短路，脏形态会被直接吃掉）。
3. 改**源批次**（`dict/src/*.json`）后重建词典，核对 `exact` 只变相关几条。
4. 验证要做**同探针 A/B**（旧词典出现双层、新词典干净），不要只看静态 diff。
