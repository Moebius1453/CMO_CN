# 变更记录

## v4.1.4 — 自动升级（开机自检 + 每 6 小时检查 + 托盘常驻）

- **新增更新助手 `CMO_Updater.exe`**（约 36 KB，与安装器同工具链、无需额外依赖）：
  托盘常驻，右键菜单提供「立即检查更新 / 打开更新设置 / 打开游戏目录 / 查看日志 / 退出助手」。
- **检查时机**：随 Windows 启动（`HKCU\...\Run`）后延迟 60 秒自动检查一次（笔记本电池模式延迟 5 分钟），
  之后每 6 小时检查一次（可在设置中改为 1/3/6/12/24 小时或仅开机检查）；休眠唤醒后按上次检查时间补查；
  手动检查随时可用。网络失败静默退避（1h→2h→6h），不弹窗打扰。
- **更新源与安全**：GitHub Releases API 比对版本 → 直连下载，失败自动切换国内镜像（默认 ghproxy，可改）；
  发布资产新增 `.sha256` 摘要，下载后强制校验 SHA256，不匹配立即删除且不执行安装；仅允许 https。
- **升级流程**：下载 `CMO_Chinese_Setup_v<ver>.exe` → 校验 → 游戏运行中先提示退出游戏 →
  以 `--install <游戏目录> --silent --wait-pid` 静默安装（安装器等待旧助手退出后再写文件，避免文件占用）→
  安装完成后自动重启助手。安装失败自动保留原文件，不会出现半汉化状态。
- **提醒与免打扰**：「不再提醒」= 关闭自动检查并记住该版本，按钮变为「开启提醒」可一键恢复；
  提醒方式可选弹窗 / 仅托盘气泡（默认，不打断全屏游戏）/ 静默。
- **安装器界面新增「版本更新」分组**：更新状态行（当前版本 / 上次检查 / 下次自动检查）、
  「立即升级」「检查升级」「不再提醒」三个按钮，以及「随 Windows 启动自动检查更新（每 6 小时）」开关。
- **卸载一致性**：还原原版英文时同时结束更新助手进程、删除开机启动项、
  注册表设置与助手本体，系统不留后台残留。
- **修复地图仍为英文（用户反馈）**：安装器从未分发汉化后的 World Wind 地名集，
  用户装包后 `WW\PlacenameSets\{Synoptic,Cities}\0000_0000.wwp` 仍是英文，
  地图上的国名/城市名以及 Stamen 标签瓦片重绘的数据源都是它。现已在安装器中内嵌并部署
  两地名集（Synoptic 321 条、Cities 4287 条，带 `.orig` 备份，卸载可还原），
  并保证先部署地名集再重绘标签瓦片；绿色包同步携带 `WW/PlacenameSets/` 目录。
  实测：把游戏地名集恢复为英文（模拟全新用户）后运行安装器 → 地名全部变中文，
  游戏世界视图园国名/海名/城市名均为中文（evidence/live/v413/v414/map_labels_world.png）。
- **修复复合串里的英文括号片段**（用户截图反馈）：任务编辑器「可用」列表的行文本是
  「苏法/风暴 #1 (Air Superiority BVR) (拉马特戴维)」这类中文+英文混排串，
  整串查表落空、按标点切分又因含中文被跳过，导致括号里的载荷名永远是英文。
  引擎新增按 `()` / `[]` 拆出纯英文片段单独翻译再拼回（支持 `A/A:` 类前缀与逗号分片），
  并补译 `[UNAVAILABLE]`→`[不可用]`、`A/A:`→`空空：`、`Light 202`→`轻载 202`、`Radar`→`雷达`。
- **彻底根治中英频闪**（用户反馈：单位状态面板「一会中文一会英文」）：
  根因是引擎此前只有一个 UI 轮询线程在补翻译（首 40 轮 600ms、之后 1500ms），
  游戏每次把实时文本（单位状态面板的 航速/深度/阵营、消息日志、状态栏）刷回英文后，
  要等下一轮才变中文，中间那段英文就是可见的频闪；经 `CTRL_TREE` 确认
  单位状态面板是 WPF 控件（`ElementHost_Right`），数据绑定会持续回推英文。
  修复：记录「确实需要翻译」的实时 WPF 元素，并挂 `CompositionTarget.Rendering`
  （每帧绘制前触发）把被刷回英文的文本立刻改回中文——英文不再有机会被画到屏幕上；
  另每 8 帧（约 130ms）全量补扫一次，保证切换单位时新建的元素也在首帧内变中文；
  仍用 `SetCurrentValue` 保留数据绑定。
  （注：曾尝试挂 WPF 依赖属性变更回调，实测会导致游戏无法启动，已弃用该方案。）
- 新增引擎诊断命令 `CTRL_TREE`（控件树导出）与 `WPF_TEXTLOG`（WPF 翻译写入日志），
  用于定位自绘/绑定界面的文本来源与频闪。
- 安装器与绿色包同步包含更新助手；绿色包解压后同样具备自动升级能力。

## v4.0.0 — 全量汉化与可验证交付

首个纳入 git 版本控制、带机械验收门禁的正式版本。

### 新增：可重现词库流水线

- `scripts/triage.py`：把引擎 28,833 条字符串池三分为
  `display`（可偏移注入）/ `label`（仅 UI 层）/ `internal`（禁译），

### 修复：三个此前未被发现的严重缺陷

1. **词库整体未生效（最严重）**
   引擎用 `text.IndexOf("\"offsets\"")` 定位分节，而新增的 `_meta.counts.offsets`
   含同名字面量，命中位置在真正的分节之前，导致四个分节边界全部错位。
   实机日志为 `Loaded dictionaries: 0 offsets, 0 exact texts, ... 21908 word roots`
   —— **上一轮交付的汉化实际上一条都没生效**。
   修复：只在根对象深度 1 处匹配分节键；`_meta` 计数键改名为 `n_offsets` 等。

2. **转义解码不完整**
   原实现只识别 `\" \\ \n \r \t`，对 `\uXXXX`、`\/`、`\b`、`\f` 会原样保留，
   含 NUL 的词条永远匹配不上。已补全为完整 JSON 转义集。

3. **词库累积过程中被写入 Lua 语句**
   增量构建时 `local roll = 10`、`endtime = '` 等可执行代码进入 `offsets`，
   正是此前 `DAL KeyNotFoundException` 与 Lua 沙箱崩溃的失效模式。
   现已建立硬性不变式：**仅 `display` 类字符串可进入 `offsets`**。
